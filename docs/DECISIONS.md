| 2026-09-27 | Ajout d'une règle CSS `@media (prefers-reduced-motion: reduce) { [data-reveal] { opacity: 1 !important; transform: none !important; } }` dans `globals.css`, en complément de `MotionConfig reducedMotion="user"`. | Vérifié (Playwright, `reducedMotion: "reduce"`) : la bibliothèque `motion` ne neutralise que les animations de position/transform (x, y, scale…) sous mouvements réduits, pas l'opacité (code source : `shouldReduceMotion && positionalKeys.has(key)`). Sans ce correctif CSS, les cartes `Reveal` continuaient de s'estomper en fondu (opacity 0→1 sur 500 ms) malgré la préférence système, ce qui contredit la règle non négociable 4 (« aucune animation », § validée manuellement : opacity reste à 1 en continu avec le correctif). |
| 2026-09-27 | Phase 7 (QA) : forme décorative du hero (`hero.tsx`) rendue responsive — `inset-0` (pas de décalage, pas de rotation) en dessous de `sm`, `-inset-3 rotate-2` (valeurs du plan) à partir de `sm:`. | Un test Playwright automatisé (largeurs 320/360/390/768/1024/1280/1440 px) a détecté un débordement horizontal réel de la page à 320 px (18 px), causé par cette forme `-inset-3 rotate-2` associée au hero : à cette largeur, la colonne image touche déjà la marge de 16 px, et le décalage négatif + la rotation la faisaient sortir du viewport. Résiduel après correctif : 1 px (arrondi sous-pixel, non perceptible, sans effet sur `overflow-x`). |
| 2026-09-27 | Ajout de Google Tag Manager, demandé par Arthur (snippet standard GTM-PW4JQVPC), en écart assumé avec la règle non négociable 5 (« aucun script tiers au chargement ») et §13 du plan (« le site n'en pose aucun [cookie] »). Choix retenu parmi 3 options proposées : GTM chargé uniquement après consentement explicite (bannière), jamais au chargement de la page. Implémentation : `src/components/analytics/cookie-consent.tsx` (nouveau composant client, cinquième après les quatre listés par la règle 1 — écart documenté ici), monté dans `layout.tsx`. Ne rend rien si `NEXT_PUBLIC_GTM_ID` (nouvelle variable d'env, optionnelle, absente par défaut) n'est pas définie : fonctionnalité désactivée par défaut, aucune régression sur les sites/environnements sans cette variable. Bannière « Accepter »/« Refuser » avec choix persisté (`localStorage`), rouvrable via lien « Gérer les cookies » en pied de page (`SiteFooter`, affiché seulement si la variable est définie) pointant vers `#cookies`. Le script GTM (`next/script`, `strategy="afterInteractive"`) n'est injecté que si le choix stocké est « accepted ». | Rendre GTM RGPD-compatible avec un site actuellement « zéro cookie » sans bannière (§13 du plan) : sans consentement préalable, GTM peut déposer des cookies dès son chargement dès qu'un tag (GA4, Ads…) y est configuré côté Google, ce qui aurait nécessité une bannière de toute façon — GTM ne peut donc pas être ajouté sans cette dérogation aux règles 1 et 5. `/confidentialite` mis à jour en conséquence (section dédiée, visible seulement si `NEXT_PUBLIC_GTM_ID` est définie). |
| 2026-09-27 | Le snippet GTM fourni comporte aussi un `<noscript><iframe…>` à coller juste après `<body>`. **Volontairement omis.** | Ce bloc `<noscript>` s'exécute précisément quand JavaScript est indisponible — donc quand la bannière de consentement (qui dépend de JS) ne peut ni s'afficher ni être respectée.
